# S6 独立脱敏盲测交付契约

2026-10-25 门槛计算组件已提供，但不代表盲测已批准或完成：`assess_quality(policy,evidence,expected_binding,now=<UTC>)` 只校验结构、绑定和数值。报告 scope 固定为 independently_reviewed_generation，与检索评分函数的 retrieval-only 输出明确分离；调用方须自行核验真实来源、独立审阅身份与事实。policy 必须显式给出 min_cases（至少 200）、min_supported_rate、min_refusal_rate、max_p95_ms、max_cost、currency、max_age_seconds 和 schema_version=1；比率/金额/毫秒用十进制字符串，不用浮点数。没有默认业务阈值，也没有自动审批/切流。本地单测中的 95%/90%/1 秒等仅是合成比较样例，不是业务冻结或实测成绩。

状态：等待业务方提供并批准真实脱敏样本。本文只定义安全交付与判定方式，不含真实问题、文档或联系人；合成开发集不得冒充盲测。

## 样本交付

- 至少 200 条互不重复的真实客服问题，由未参与 Embedding／Reranker／门控调参的人员抽样、脱敏、标注并冻结。按租户和权限、可回答、缺失事实、冲突、型号精确匹配、口语改写、跨文档、图片／表格引用分层，记录每层数量。
- 数据集放在仓库外的受控私有位置，不提交 Git、不上传在线模型。问题中的姓名、联系方式、订单号、企业未公开名称等须先替换或删除；保留型号语义时使用获批准的脱敏映射。
- 每条记录使用稳定 `case_id`、`tenant_alias`、`role`、`question`、`answerable`、`category`、`expected_facts`、`forbidden_claims` 和 `expected_sources`。来源标注需能映射到固定文档 ID、版本、切块内容 hash；不可只写“某文档大概相关”。缺失事实题的 `expected_sources` 可为空，但须写明拒答所针对的事实。
- 另存受控映射文件，将 `tenant_alias`、脱敏文档引用映射到隔离验收库。映射及可识别原始数据不得进入公开报告；报告只保留 case_id、类别、计数、结果和失败原因代码。

合成格式示意（不能计入 200 条）：

```json
{"case_id":"SYN-001","tenant_alias":"synthetic-a","role":"customer","question":"退货需要哪些资料？","answerable":true,"category":["口语改写"],"expected_facts":["需订单号","需产品批次"],"forbidden_claims":[],"expected_sources":[{"document_ref":"synthetic-return-guide","version":1,"content_sha256":"<64位哈希>"}]}
```

## 冻结与评分

1. 业务、产品、安全和运维共同确认脱敏、租户边界、抽样方法、题目／答案标注、目标门槛与审阅人；对数据集文件和来源映射分别记录 SHA-256、批准时间和访问角色。开发集与盲测集必须分开；看过盲测答案后调整检索或门控，须换新的独立盲测集。
2. 在同一冻结文档快照和权限配置下，分别运行词法、向量、融合、融合＋重排、融合＋重排＋证据门控；保持每组参数和模型 revision 可复现。记录 Recall@3、错误型号、空召回、拒答、引用支持率、跨租户泄漏、P50/P95、GPU/CPU 资源与在线费用。
3. 对生成答案由至少两名独立审阅者逐事实核对原文、版本及权限，分歧复核；只要引用不支持关键事实，就不能算“引用支持”。Reranker 分数和有 citation 字段都不是事实支持证明。
4. 暂按 [RAG 升级方案](rag-upgrade.md)的建议门槛评审：至少 200 条独立真实脱敏问题、生成引用支持率 ≥95%、缺失事实正确拒答率 ≥90%、跨租户泄漏 0，检索 P95 初始目标 ≤1 秒。最终数值须在 S0 批准后冻结；样本量、分层置信区间和失败案例数量一并报告。
5. 只有安全审阅、双机运行、正式告警和回切演练都通过，才允许从 shadow 到内部灰度、小流量客户灰度。任一阶段发现权限泄漏、错误引用或门控退化即回切，保留旧索引和审计证据。

当前尚无已批准的数据集、来源映射或独立评分结果，S6 不能验收。

结构检查入口：在项目根目录运行 `python -m scripts.validate_rag_blind_set <仓库外受控JSONL路径>`。它只输出文件 SHA-256、样本/可答数量和类别计数，不输出题目、事实或来源；不足 200 条、重复 ID、缺失标注或无效来源版本/hash 会拒绝。此检查不识别个人信息、不证明业务批准或答案正确，也不执行模型评测；脱敏和双人事实审阅仍须人工完成。

检索层评分函数 `app.rag_blind_eval.evaluate_retrieval` 已提供：调用方必须供应按 `tenant_alias`/`role` 绑定真实认证身份的 Top-3 检索适配器，并把结果映射为已批准的脱敏文档引用、版本和切块 hash。评分器先验证数据集结构与至少 200 题，运行后复核文件 SHA-256，输出可答题命中率、预期来源 Recall@3、无结果数、跨租户结果数、分层计数及 P50/P95；不输出问题、来源身份或正文。跨租户候选不能计为命中。当前仅用 200 条合成题验证评分逻辑，尚无业务批准数据或生成答案双人事实审阅，不能把此函数输出直接视为生产盲测报告。

现已加入 `app.rag_blind_adapter.AuthenticatedBlindSearch`：批准的受控运行器在内存中注入各 `(tenant_alias, role)` 的可撤销登录令牌和完整私有文档引用映射，不从环境变量或报告读取／输出令牌。每题重新解析真实数据库身份，严格核对租户及角色，使用 token-bound `KnowledgeRepository`/`KnowledgeService` 检索；未知身份、缺少映射、跨租户返回或令牌撤销均失败关闭。若启用本地混合检索，同一评测实例固定 active 索引身份，切流后停止评分。隔离 PostgreSQL 合成双租户测试已覆盖这些身份边界；还缺业务方批准的令牌供应流程、私有映射、真实题集与独立双人评分，不得把适配器存在视为盲测通过。
