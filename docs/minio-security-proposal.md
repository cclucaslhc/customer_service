# MinIO 私有对象存储候选安全方案（待批准）

状态：仅供审阅，未批准、未实现、未通过生产验收。当前 AWS PublicAccessBlock 门禁及失败关闭行为保持不变。

## 为什么需要单独决定

本批独立 MinIO 对标准 SDK PutPublicAccessBlock 请求返回 MalformedXML。当前服务不能证明生产要求的四个公开访问阻断标志已生效；私有 ACL、匿名访问失败或版本化成功均不能单独替代它们。不能根据自动 continuation 推定用户批准安全契约变更。

可选方向：继续要求完整 AWS 风格契约并接入符合要求的批准服务；或另行批准 MinIO 专用安全基线。推荐自管需求采用后者，但必须保留等价控制和供应商差异，不能称二者机制相同。

## 候选设计（不是现有能力）

- 默认仍为现有严格模式。MinIO 模式只能由部署方对确切 endpoint/bucket/region 显式启用，普通管理员表单不能任意切换供应商安全基线；不得根据 API 报错自动降级。
- 保持 HTTPS、证书与主机名验证、批准目的地、版本化、固定 VersionId、读回 SHA256 校验、租户引用校验及实时权限复查，不提供远端 loopback 豁免。
- 独立基础设施管理员负责桶策略/IAM；应用账户不是 root，禁止修改桶策略、ACL、版本化、账户或其他租户资源。API/Worker/备份按所需操作划分身份，应用日志不包含密钥。
- 每租户独立桶或可证明的独立前缀授权；数据库加密配置只能绑定本租户目标与版本。不能只靠应用 key 前缀检查承担全部底层隔离。
- 部署校验器以独立、受限的审计身份检查有效桶策略及身份授权，拒绝公共 Allow、未知/无法解析语义和权限超集。身份策略、桶策略、用户组及继承必须合并评估；仅 GetBucketPolicy 不足以证明服务账户最小权限。
- 审计通过的证据必须绑定服务身份、目标、策略摘要、版本和有效期。策略漂移、凭据轮换、证据过期或审计不可用时，拒绝新写入/发布；不能永久缓存一次匿名探测成功。
- 验收既检查配置，也执行匿名/错误身份/其他租户拒绝及正确身份允许；探针仅操作独立合成桶和对象，不读取真实公司数据。
- 备份与恢复继续强制 recovery hold/rebind；切换安全基线或目的地不能静默重解释历史引用。新模式的指纹必须绑定基线版本，旧指纹不自动升级。

## 必须证明的验收项

| 验收范围 | 要求的直接证据 |
| --- | --- |
| 远端 TLS | 两 guest 都成功校验批准证书；错误 CA/主机名拒绝 |
| 配置隔离 | 应用身份不能改策略/ACL/版本化或管理账户 |
| 资源隔离 | 匿名、错误凭据和其他租户读写均拒绝，授权读写成功 |
| 策略漂移 | 注入公开策略/权限超集后，审计拒绝且发布停止 |
| 版本与完整性 | 覆盖后仍读取固定旧版本；缺版本/摘要不符失败关闭 |
| 跨节点导入 | API1上传合成文档，Worker2无共享本地原文仍可解析发布；API1/2检索一致 |
| 不确定结果 | 上传/发布回执丢失不盲删版本、不重复发布，残留可对账 |
| 恢复 | 加密备份恢复、旧凭据隔离、匹配目标重新绑定、引用读回 |
| 重启 | 两节点及对象服务重启后可恢复，证书/身份/证据过期仍拒绝 |

匿名探针通过不证明未来不能被设为公开；策略摘要不证明 IAM 已正确合并；同宿主双 guest 不证明物理容灾。任一项缺证据都不能把 MinIO 模式列为生产完成。

## 审阅节点

需要用户明确批准是否采用上述新安全基线，再进行相关业务代码、配置格式及指纹变更。批准方案也不等于批准上线、公网暴露、访问生产凭据或采用不受控模型。批准前只可继续原有模式下不受影响的开发与隔离验证。
