# 灰度阶段推进与最终提升（0037内部服务）

`RagRolloutService.advance`已实现owner受控的一步推进，不是自动调度器或公开HTTP入口，也不表示已经部署生产。head仍0037，无新迁移；真实业务审批、自动异常动作和完整生产验收仍未完成。

## 事务边界

每次调用必须明确tenant、rollout/version/plan摘要，以及release/version/body摘要和由可信控制器提供的当前绑定。服务取得排他发布锁、锁定rollout和release，验证当前阶段与冻结计划一致、质量证据仍有效、baseline仍active/candidate仍ready且manifest未变，并复查两名指定管理员当前会话及权限。不能通过额外参数跳阶段或提交外部观察报告。

服务在同一事务内重新读取PG观察窗口并评估。缺样本、时长不足、pending、未知费用、错误率/P95/单轮费用超限等均拒绝，阶段状态不变；先前observe绿色报告不能覆盖新出现的pending请求。满足条件只进入冻结steps_bps的下一步，version+1并使用数据库当次时间建立新epoch；旧epoch样本不能满足新阶段。审计保存本次聚合报告、评估及摘要，不含问题/答案、用户行或会话摘要。

最后一步10000不是简单修改百分比：在同一事务内激活candidate、退休baseline、把release转为executed并增版本、把rollout转为completed/10000并写审计。耗时manifest工作后再次检查质量/窗口新鲜度、期限和双方会话，再消费审批。任何审计或写入失败，索引、审批和阶段一起回滚。completed不可重放。最终step_started_at保留最后一个受观察阶段的历史起点，不宣称已观察100%流量。

运行器在事务提交后看到新route version；旧快照必须重验。最终提升后新轮次走新的全租户active索引，灰度投影消失，不需要保留已消费审批来继续读取已发布索引。旧run不会自动重启或重放模型调用。

## 限制

当前gate要求候选窗口没有pending请求，繁忙持续流量可能使推进持续等待；尚无独立drain/自动观察调度，也未做生产负载验收，不能承诺不停流灰度吞吐。观察仅是操作健康，不证明事实支持率、拒答质量或真实费用结算；这些仍依赖独立业务证据、真实模型/服务revision及账单验收。合成费用记录不作为实际计费证明。

审批/证据有效期必须覆盖全部阶段的最低观察时间及执行余量；过短的合成测试计划可以启动但不能完成长观察，过期时失败关闭。服务不延长旧审批、不复用旧窗口。不健康当前只拒绝推进，不自动暂停/回切；成功提升后回退也需独立受控流程，现有rollback仅撤回未完成灰度。
