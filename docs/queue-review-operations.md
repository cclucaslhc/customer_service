# 终态队列只读核对

状态：已提供受限只读清单；聊天任务仅有可证明首次模型调用前的单次重排队，尚无通用自动重试、确认/关闭死信或生产 RLS 适配。只有具备正式值班授权的人员可在批准环境执行；报告中的租户 ID 和任务 ID 仍是内部元数据，不应发往公开日志或外部工单。

聊天、知识任务可能在外部模型调用、工具执行或文档发布时失去执行租约。聊天任务只有在数据库证明首次模型尝试尚未开始、也没有工具/输出等效果时，才能自动重新排队一次；一旦模型尝试已入账或证明不足，失租后终结并拒绝旧 Worker 的迟到写入，**不盲目重放**。知识任务失租仍直接终结。清单将已终结的异常任务分为：

| disposition | 含义 | 操作 |
| --- | --- | --- |
| `terminal_no_execution` | 排队超时、身份失效或会话在领取前失效；没有本次 Worker 执行 | 核对用户请求与身份后，由用户明确提交新的任务；不要修改旧任务状态 |
| `review_unknown` | Worker 失败、失租或协调中断；外部调用/部分发布可能已经发生 | 先核对模型用量、工具流水或知识文档/对象版本；不得仅因任务失败而自动重试 |
| `review_items` | 知识任务部分或全部文件处理失败 | 查看授权管理界面的逐项结果，核对已发布文档，再决定是否重新提交未完成输入 |

CLI 只接受已有、权限私有的数据库 URL 文件，不从环境中搜索凭据，不回显 URL。使用独立的 PostgreSQL 只读角色（现有备份角色可作为授权基础，但应由 DBA 审核额外访问范围），不得使用 API、Worker、迁移或超级用户角色：

```bash
python scripts/queue_review.py \
  --database-url-file /run/customer-service/queue-review-database-url \
  --limit 100
```

远程 PostgreSQL 连接仍须 `sslmode=verify-full`。查询事务为 `READ ONLY`，启动时检查角色无数据库/Schema 创建能力、无 public 表写权限或序列写权限，只读取 `agent_runs` 与 `knowledge_jobs` 的固定字段；默认最多 100、硬上限 200，5 秒语句时限。输出仅含任务类型、任务/租户 ID、终态、固定原因/处置分类、完成时间及知识已处理数；不含聊天正文、Prompt、文件路径、原始异常、模型供应商、密钥或逐项结果。用户取消、被新问题取代的聊天任务不列入异常清单。清单不会领取、重排队、删除或确认任何任务。

如果目标表启用 RLS，此入口会拒绝运行，而不是返回可能不完整的“空清单”。S1 的可信跨租户审计/备份读策略完成后，必须按新政策更新并重新做直接 SQL 越权测试。该清单不是完整死信状态机：尚缺审批/责任人、对账结果、可审计确认、受控安全重试和保留期；不能据此勾选 S3。
