# RAG 耐久审批存储（0031）

当前完成独立存储、权限和恢复边界，并新增仅供 owner 受控调用的 `RagReleaseService`，含一次性原子发布 `execute`，**尚无 HTTP/UI 审批入口、自动调度、灰度控制或自动回切**。不能凭数据库 state=approved 或两段哈希认为已获真实批准；现有手动 owner 激活 CLI 尚不消费此表。

服务冻结质量策略、证据和上下文绑定，校验实际 active 基线、ready 候选和 manifest；两名指定的同租户管理员须分别提供当前有效的原始登录令牌。持久化仅保存会话摘要；每次批准及 readiness 复查角色、账户、租户、撤销和实时过期，按 version/hash 拒绝旧回执，审批更新与审计同事务。当前绑定必须由可信控制器提供，不得回显用户请求充当事实。`check_ready` 仅是当次事务的检查结果，绝不能先检查、另起事务激活；后续执行器必须在激活事务内重验。合成证据测试不证明业务方独立审阅或真实生成质量。

可选 `rollout_plan` 同样冻结在审批正文hash内；灰度计划不能在批准后另传修改，也不能通过一次性execute跳过。owner灰度staging服务只从已批准且双方会话仍有效的计划创建零流量记录，见[灰度边界](rag-rollouts.md)。未包含灰度计划的旧记录不能自动获得灰度权限。

## 冻结对象

`rag_release_intents` 使用 `(tenant_id,release_id)` 主键，绑定同租户的候选/旧索引和两名不同成员引用。SQL 外键阻止跨租户索引/成员引用，约束阻止候选等于旧索引、两审阅人/两会话摘要相同、过期时间不晚于创建时间、超大正文或 approved/executed 缺少两份会话摘要。数据库只验证成员引用和字段形状，不验证他们当前是管理员或真的审阅了业务答案。

body（最多 64 KiB）、body_sha256、目标索引、审阅引用和创建/到期时间不可更新；改变审批对象须创建新 release_id。可变状态每次更新的 version 必须恰增 1，服务按 expected-version CAS 拒绝旧回执。服务验证 body 完整性、管理员权限、两份可撤销会话与审批主体匹配、质量阈值和控制器提供的当前模型/Prompt 绑定，SQL 形状不代替这些检查；证据是否由业务独立审阅仍需可信来源证明。

`execute` 在同一事务内持有发布锁与身份行锁，复查证据/审批后调用共享事务的索引激活，将审批转为 executed 并递增 version，写入激活和消费审计；任何失败整体回滚。manifest 校验后再次检查会话及审批期限，避免耗时检查期间过期仍发布。executed 不可重放；不提供“失败后盲目重试”语义，应先核对真实状态。此接口尚未接到 HTTP/CLI，也不提供分批灰度或自动回切。

`reject` 允许指定的当前有效管理员，凭匹配 version/hash 和仍有效的上下文，将 pending/approved 计划终止为 rejected；保留历史审批摘要并写同事务审计。它不能恢复、不能重新批准或执行，须新建计划；不等于运行中灰度暂停。过期或已失效上下文已无法执行，当前接口也不会将其改为 rejected。API/Worker 仍无直接权限，不可把 owner 服务公开成未鉴权调用。

## 最小权限与维护

新表默认撤销 PUBLIC 权限，运行角色授权脚本明确撤销 API/Worker 对整表的所有权限，启动角色门控也拒绝拥有其 SELECT/INSERT/UPDATE/DELETE 的服务身份。备份角色仍按既有受控全库只读协议访问，没有对 HTTP、SSE、日志或指标开放审批摘要的入口。字段设计仅用于会话摘要，不应写入明文 Cookie、令牌或模型 Key；body 的严格内容检查仍需后续服务实现，不能把任意 JSON 存储当成自动脱敏保证。

新表进入全局维护触发器及显式 SHARE 封存清单，当前为 44 业务表、4 协议控制表。恢复在原始快照验证后，把 pending/approved 置为 recovery_review 并递增版本；冻结正文和历史审批摘要保留，清除 recovery hold 本身不能把旧审批恢复为可执行。executed/rejected 的历史状态不重放。恢复重置 SQL 已直接在真实 PG 测试，**本批尚未进行带审批记录的加密备份/恢复验收**。
